## 1. WHAT ALGORYXZ IS

Algoryxz is an AI-native digital studio founded by three engineering/design students (Smarak, Deeptiman, Akriti) based in Odisha, India. 

Internally, Algoryxz uses AI coding agents, automated pipelines, and modern serverless infrastructure to achieve high velocity and low operational cost. **Externally, AI is not the sales pitch.** 

Clients buy:
* **Taste & Judgment:** Design that looks bespoke, not like a template dump.
* **Engineering Rigor:** Sites that are fast, accessible, mobile-optimized, and backed by robust code.
* **Founder Directness:** Working directly with the people building the product, without agency overhead or junior relay chains.
* **Speed & Accountability:** Days-not-months delivery with clear scope, fixed boundaries, and reliable post-launch support.

### The Three Operational Lanes

1. **Celebrations (Occasion Experiences):**
   * *Scope:* Weddings, proposals, anniversaries, birthdays, personal interactive events.
   * *Character:* Emotion-driven, highly visual, mobile-first, experiential.
   * *Business Role:* High margin-per-hour wedge, rapid turnaround (3–7 days), word-of-mouth engine.
2. **Business & Brand (Commercial Websites):**
   * *Scope:* Cafés, restaurants, salons, gyms, creators, photographers, startups, local professional businesses.
   * *Character:* Conversion-oriented, menu/services/catalog display, location/contact routing, basic CMS.
   * *Business Role:* Foundation for recurring monthly maintenance (Care plans).
3. **Custom Systems (Advanced Capabilities):**
   * *Scope:* Custom booking workflows, multi-role auth, dashboards, databases, payment gateways, custom web applications.
   * *Character:* Logic-heavy, backend-dependent, individually scoped.
   * *Business Role:* High-ticket revenue; surfaced as an upsell/extension, not a commodity package.

## 4. PROJECT CLASSES & INTERNAL SCOPING

Projects are never priced strictly by page count. Scoping is evaluated across eight dimensions:

| Dimension | Low Complexity (1) | High Complexity (5) |
|---|---|---|
| **Design Depth** | Template-adjacent layout variant | Bespoke art direction, custom assets, motion choreography |
| **Functionality** | Static presentation, basic contact form | Complex forms, multi-step filters, dynamic calculators |
| **Integrations** | Maps embed, WhatsApp click | Razorpay/UPI gateway, SMS APIs, calendar synchronization |
| **Content Burden** | Client provides complete, formatted text & images | Studio must source stock, draft copy, or edit raw media |
| **Data / Backend** | Zero database required | Relational schema, user auth, dynamic CMS, admin panels |
| **Risk & Compliance** | Low-stakes informational page | Handles attendee/customer PII, guest lists, payments |
| **Urgency** | Standard 2–3 week window | Rush turnaround (< 5 days) — warrants 25–50% surcharge |
| **Client Value** | Personal portfolio / hobby | Revenue-critical transactional storefront or booking system |

### Classification Tiers

* **Class C (Celebration):** Low technical risk, high aesthetic demand. Static or light serverless (RSVP to D1/Neon). Built in 3–7 days. Productized tiers.
* **Class B (Business & Brand):** Standard commercial presence. Static or JAMstack + light CMS + contact/booking triggers. Built in 1–3 weeks. Base package + named add-ons.
* **Class X (Custom System):** Multi-role auth, databases, bespoke business workflows, admin dashboards. Built in 3–8+ weeks. Milestone-based contracts only.

## 7. SCOPE, REVISIONS & CHANGE DISCIPLINE

Scope creep is the primary failure mode of small digital studios. The following policies are mandatory in every SOW:

### The 2-Revision Standard
* Every fixed-price project includes **exactly two (2) consolidated revision rounds**.
* **Definition of Revision:** Adjusting, tweaking, or polishing elements *within the agreed scope* (changing copy, swapping an image, adjusting colors, shifting layout blocks).
* **Batching Rule:** Revisions must be submitted in **one batched list** per round. Trickling feedback over WhatsApp voice notes or scattered messages is rejected.
* **Definition of New Scope (Change Order):** Adding sections not in the initial spec, creating new pages, adding database tables, integrating new third-party APIs. New scope is paused, estimated separately, and billed before execution.
* **Bug Fix Guarantee:** Any technical bug (broken link, form failure, layout breakage) within the agreed spec is fixed free of charge for 30 days post-launch. Bug fixes do not consume revision rounds.

### Scope Communication Habit
Every verbal or WhatsApp agreement must be recorded in writing by the Client Owner:  
> *"Confirming our call: we will swap the gallery layout as your Round 1 revision. Adding an online table-booking system was not in the original quote; we can build that as an add-on for ₹4,500 with 3 extra days. Let us know if you want to proceed with that addition."*

## 8. DOMAIN & ASSET OWNERSHIP

Algoryxz does not hold client assets hostage. Trust and clean boundaries are core differentiators.

1. **Domain Registrant Rule:**
   * The **client is always the legal owner and registrant** of their domain name.
   * Algoryxz never registers a client domain under a founder's personal name or studio account.
   * *When client asks "Handle it for me":* The studio guides the client through registration, or sets up the registrar account using the client's email and legal details, adding Algoryxz as DNS technical manager.
2. **DNS Management:**
   * Handled via Cloudflare. Pointing nameservers to Cloudflare allows Algoryxz to manage SSL, performance, and Pages deployments without owning the underlying domain asset.
3. **Exit Autonomy:**
   * If a client terminates a maintenance contract or leaves, Algoryxz hands over all DNS records, source archives, and assets unconditionally within 5 business days, provided all past completed milestone invoices are paid.

### Hosting Decisions & Explicit Rejections

* **Cloudflare Pages:** **DEFAULT HOST** for all Celebrations and Business & Brand static/JAMstack sites. Commercial use is explicitly permitted on the free tier.
* **Vercel:** **REJECTED FOR HOBBY TIER.** Vercel Hobby strictly prohibits commercial use. Vercel Pro ($20/seat/mo = $60/mo for 3 founders) is used *only* if a client explicitly funds a complex Next.js SSR architecture.
* **Netlify:** **REJECTED AS PRIMARY HOST.** Hard credit caps (300 credits/mo) cause unexpected mid-month outages.
* **Third-Party Form Services (Formspree/Basin):** **REJECTED.** Form submission logic is handled via a native 20-line Cloudflare Worker posting to Resend and logging to D1/Sheets, saving monthly fees and avoiding submission caps.

## 12. SECURITY & CREDENTIAL STANDARDS

Security must be proportionate: high rigor where data is at stake, zero enterprise bloat on static brochure pages.

### Non-Negotiable Standards (Client #1 Onward)
* **Founder MFA:** Time-based one-time password (TOTP) hardware/app MFA mandatory on all primary accounts (GitHub, Cloudflare, Supabase, Bitwarden, Razorpay).
* **Zero Secrets in Git:** API keys, database connection strings, and service tokens are never committed to repositories. All secrets live in Cloudflare Pages environment variables or GitHub Actions Secrets.
* **Centralized Credential Vault:** Client logins, server credentials, and recovery keys must be saved in the shared Bitwarden studio vault. No credentials stored exclusively in a single founder's private notes.
* **Encrypted Handovers:** Sensitive credentials or environment variables transferred to clients must use **Bitwarden Send** (with password protection and a 48-hour expiration). Plaintext email, WhatsApp, or Google Docs transfers are strictly forbidden.

### Tiered Security Controls
* *Class C (Celebrations):* Basic form sanitization, signed R2 upload URLs, no server-side secrets exposed.
* *Class B (Business):* Webhook HMAC signature verification (Razorpay/WhatsApp), dependency vulnerability scanning via `npm audit` and Dependabot, form rate limiting.
* *Class X (Custom):* Supabase Row Level Security (RLS) enabled on all tables, automated cross-tenant data leak tests before launch, HTTPS-only secure session cookies, dedicated staging database.

## 14. AI AGENT CONSTRAINTS & SAFEGUARDS

AI coding agents are heavily leveraged within Algoryxz repositories. All agents operate under strict constitutional sandboxes:

### Autonomous Agent Permissions
* Read codebase files, issue trackers, and internal documentation.
* Create, branch, and commit to non-production feature branches (`feature/*`, `fix/*`).
* Execute local test suites, linters, formatters, and type checkers.
* Propose Pull Requests with structured changelogs.
* Trigger ephemeral preview builds for QA inspection.
* Generate draft database migration scripts for human audit.

### Prohibited Agent Actions (Mandatory Human Sign-off)
* **Direct pushes or merges to production branches (`main`/`master`).**
* **Executing database migrations or destructive schema alterations against live production databases.**
* **Modifying DNS records, domain ownership, or SSL configurations.**
* **Accessing live banking, payment gateways, or customer financial accounts.**
* **Permanently deleting production files, databases, or S3/R2 storage buckets.**
* **Self-assigning or escalating administrative infrastructure credentials.**
